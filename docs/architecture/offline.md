# Offline use on phones and tablets

Part of the notes on how Plant record is built. The short map is `docs/ARCHITECTURE.md`; this file holds the detail for one area, moved here word for word on November 15, 2026.

## Notes
- **1.24.0 (offline use):**
  - **Service worker** `app/static/sw.js`, served at `/sw.js` by `service_worker()` with the version substituted, so each update installs a new one:
    - the app's files and `/api/` GETs are network-first with a 5 s timeout, then the saved copy (`X-Offline-Saved` header); after a failure it uses saved copies at once for 30 s;
    - photos are cache-first;
    - `NO_SAVE` lists the answers never kept (people, backups, audit, keys, status).
  - Manifest and icons in `app/static/`.
  - **Device side** (app.js, "offline use"):
    - IndexedDB `plantdb-offline` with `outbox` (changes waiting), `finds` (finds made offline, code `NEW-…`, photos as Blobs), `idq` (pictures for Identify) and `kv` (keep, keeplib, device name, idmap from NEW- to F- codes, downloaded).
    - `api()` puts queueable changes (`OFF_OK`) in the outbox when offline or when the fetch fails, and returns a stand-in answer. Every queueable request carries an `X-Offline-Op` id.
    - `offQueue()` adds `base_values` (what the device saw) to PUTs and patches the saved answer so the page shows the change. `offSync()` sends the outbox in order on `online`, every minute and at start, rewriting NEW- codes.
    - `offDownload()` saves what `/api/offline/manifest` lists, plus every photo. `OFFLINE_PAGES` and the per-plant and per-find lists were recorded by visiting every page.
    - The library falls back to `/api/library/offline-index` (`offLibBrowse()`).
  - **Server:**
    - `offline_replay()` (end of `guard()`) answers a known `X-Offline-Op` from `sync_ops`, and `offline_remember()` (after_request) keeps new answers.
    - `merge_fields()` is used by `PUT /api/plants/<code>` and `PUT /api/fungi/<code>` when the version moved on and `base_values` came with the edit. Fields only the device changed are applied, and clashes go to `sync_conflicts`.
    - `/api/conflicts` and `/api/conflicts/<id>` (`choice`: phone or server).
    - Audit kind `sync`. CSP allows `blob:` images and connections, for photos kept on the device.
  - **Tests:** `offline_check.py` pauses the mock server (SIGSTOP), because Playwright's offline switch doesn't reach service-worker requests.
  - **1.40.0, one identifier:** `identify_pictures(c, pics, scope, exclude, exclude_genera, plant_code, plantnet, n)` in identify.py (library.py before 1.57.0) is the one path: the vision call with every picture (`n` asks for extra names to cover exclusions), `rejections()` from the new `id_rejections` table (plant-bound; session-bound ones come from the client as `?exclude=A|B&exclude_genera=G`), `plantnet_ask(c, pic, more)` when wanted ('yes', or 'auto' with the setting and unsure), the merge (score = local probability + 1.3 × Pl@ntNet score; renormalised; `sources`, `plantnet_probability`), `mark_owned`, `basis_words`, `genera` and `families` over the merged list. Routes: `POST /api/identify` (+ `exclude`, `exclude_genera`, `plant`, `plantnet`, `n`), `POST /api/identify/reject` ({name, genus, plant}), `POST /api/plants/several/identify` ({photos, exclude, exclude_genera, plantnet}: pending files read from `PENDING_DIR`); `/api/plants/several/photo` now goes through the same function (one picture, no Pl@ntNet, 5 names) for the first grouping guess. Front end: `idNamesPanel(r, o)` (identify.js; discover.js before 1.57.0) renders the list everywhere; `spCard(s, i, src, withAdd, o)` adds the `tag-src` tags, a pick radio (`o.pick`), `o.use` ("Use this name") and `idnot` buttons (`o.reject` = 'id' | 'sev' | 'new'); `idNot()` keeps the exclusions per shot (`ID.shot.ex`), per Add-several plant (`P.ex`) or per form (`NEWID.ex`), posts the rejection when the user can change things, and re-asks. Add several: `sevIdentify(gi, force, plantnet)` (keyed by photo set + exclusions, result in `P.id`), `sevIdentifyAll()` after grouping and regrouping, `sevDrawPlant(gi)`; acts `sevrecheck`, `sevask`. Add a plant: `newfill` sends all photos, `newuse` fills the fields. Plant page: `POST /api/plants/<code>/identify` (its newest six photos, main first, `plant_code` bound so `id_rejections` apply; its own code dropped from `matches`), `plantIdentify()` into `#plant-id`, acts `plantid`, `plantask`, `plantuse` (PUT with the names and a note). Mock vision honours `n`.
  - **1.39.1, room for the content:** `filterFold(inner, n, hint)` and `moreFilters(extra, extraOn)` in gallery.js build the `<details class="more-f" id="more-f">` box (open while `MOREOPEN` or any folded filter is on); `.filters-main` is the one visible row. Used on the Plants page, Identify's photo table and the Library (the Audit log has its own `#aud-fbox`, now closed unless `audInUse()`). `buildSideNav()` sets `data-navempty` when only "Top of the page" exists and `navOpen()` then answers false (CSS hides `#nav-tab` too). `h1:has(+ .rd-page)` puts the read-aloud row beside the title on wide screens. Lights: the inline-edit grid `.lt-ed` is `hidden` until `ltedit` toggles it; the values show in `dl.lt-facts`.
  - **1.39.0, identification:** `vision/service.py`: `embed(img, views)` averages `views_of()` (as is, letterboxed, middle 60%); `embed_many()` averages several pictures (`image` + `images`, up to 6); `photo_rows()` carries the plant's scientific name and `PHOTOS['sp']` holds each photo's species index (`species_index()`), `own_names()` the record's species and genera; `/identify` scores the top 80 names, then adds `PRIOR` (own_sp 1.5, own_gen 1.0, house 0.7, state 0.3, looks up to 3.0 scaled by similarity above `NOVEL`) with `prior_why()` and the look-alike photos (top 8 by similarity, named plants only), returns 10 species with `basis` and 5 genera, `pictures` and `prior`; `VISION_PRIOR=0` turns it off. App: `pictures_bytes()` forwards every picture; `/api/identify` adds `basis_words` and, with setting `plantnet_auto` and a key, `plantnet` (from `plantnet_ask()`, shared with `/api/identify/plantnet`) when no sure match and the best name is under 0.5. Front end: `idAsk(blob, scope, more)`, `idAddShot()` / `idMoreFile()` / `idSnapMore()` (`ID.shot.more`), `.id-fold` hides names 6–10 (`idmoresp`), `spCard` shows `basis_words` as "Lifted: …" tags, the Pl@ntNet block paints first and `ID.shot.plantnet` feeds `spFrom('plantnet')`. Tests: `test_vision_prior.py` (stand-in model), `identify_check.py`, mock vision returns 10 names with `basis`; `dev/vision/prior_test.py` measures the prior on real photos.
  - **1.38.0, phone and offline:**
    - `OFF.reach` ('yes'/'no') says whether the plant server answered last time, separately from `navigator.onLine`: `offSeen()` sets it from every GET (an `X-Offline-Saved` header or a failed fetch means 'no'), `offDown()` starts a 30 s probe timer, `offUp()` (first answer after 'no') sends the outbox, toasts and re-routes unless a form is open. `offProbe()` fetches `/api/offline/status?nosave=1` with `X-Probe: 1`; `sw.js` lets such a request through its back-off (`downUntil`) and clears the back-off when it answers. `quick()` in the worker no longer trusts `self.navigator.onLine`. `data-act="offtry"` is "Try to connect now" (offline note, Offline page). The offline note is drawn whenever the server is out of reach, not only when the page carried the header.
    - `OFF_OK` grew: `POST /api/fertilizer`, `POST /api/frost/done`, `PUT /api/requests/<id>`, `PATCH /api/to-photograph/<id>`, `PATCH|DELETE /api/photos/<id>`, `POST /api/outside/porch` (the server's `offline_replay()` already handles any route with `X-Offline-Op`). `offQueue()` patches the saved answer each one shows on: `/api/fertilizer` (a pending entry), `/api/frost` (a plant leaves the list on a move, `done` on a tick, counts adjusted), `/api/requests?open=1` and the plant dict, `/api/to-photograph`, the plant's `photos`, `/api/outside.porch`, `/api/wishlist`, `/api/library/notes`; `offCachedUrls(re)` lists the saved answers to patch, `offPlantLists(code, fn)` patches the plant's entry in every saved plant list. `offNotice()` shows waiting photos as thumbnails (`.off-pics`). Not patched: `/api/prep` (the prep steps still show the old state until sent).
    - `offCareSeen()` (called from `offQueue()` for `POST /api/care`) patches the saved `/api/water` answer the way `water_report()` would (last_water/last_check, next, state) and prepends a `pending` entry to the saved `/api/care?n=12&plant=` log; the shim's `water` carries the codes. `offWhen(r)` adds "(kept on this device…)" to messages.
    - `POST /api/plants` is queueable: the op gets `temp: NEW-…`, the shim the temp code; photos then queue as `POST /api/plants/NEW-…/photos` and `offSync()`'s `idmap` turns the temp code into the P- code (same path as finds). `offIdQueue(url, form, {ref, kind: 'plant', quiet})` keeps the first photo; `offIdRun()` maps `ref` through `idmap` and skips entries whose plant is not sent yet; the Offline page offers `offiduse` (PUT the top species' names). The Plants page lists waiting new plants from the outbox.
    - Scroll memory: `SCROLLS[path]` is noted in `route()` when leaving a page; `NAVCLICK` (set by any `a[href^="#/"]` click and by `go()`) tells a link from Back/Forward (`wentBack`); `scrollBack(h)` restores at 0, 250 and 900 ms. `offNotice()` is awaited before the scroll so it cannot push the page later. `.main-photo img` and `.tl-fig img` have an aspect ratio. The error branch of `route()` sets `drawn` so the 150 ms "Loading" stand-in cannot overwrite the message.
    - Add a plant: `__photos` on the new form (`newphotos` change act enables `newfill` and drops `required` from the common name); `submitForm()` uploads them after the POST and queues the identification when the plant was kept offline; a stand-in name "New plant, date" when the name is empty. No `capture=` on photo inputs (the phone offers camera or gallery).
    - Add several: `sevPreview()` makes an 800 px JPEG preview per photo with `createImageBitmap` + canvas; `SEV.order` (by `taken`), `ph.rel` ∈ same/new/all/out with `sevFirstGuess()` (same top species at ≥ .3 → same) and `sevGroup()`; `sevPlants()` keys a plant by its first photo so typed fields survive regrouping; `POST /api/plants/several` takes `shared: [files]` and copies each onto every plant (caption "Several plants together", `shutil.copyfile`, new `up_` names).
    - `html[data-narrow="1"] .sticky-save{bottom:var(--pin-h)}` keeps a form's Save bar above the bottom bar.
    - **Tests:** `phone_check.py` runs its own mock server on 8480 so it can stop and start it; `several_check.py` follows the per-photo answers.
