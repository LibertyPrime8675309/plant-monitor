# Your own reminders (prototype)

Part of the notes on how Plant record is built. The short map is `docs/ARCHITECTURE.md`; this file holds the detail for one prototype.

- **Your own reminders (prototype proto/reminders):** `app/plantdb/reminders.py` makes its own table `plant_reminders(id, plant_code, loc_id, text, due_on, repeat_days, created_by/at, done_by/at, done_on, done_next, removed_by/at)` with `remind_tables()` (CREATE IF NOT EXISTS, checked against `sqlite_master` on each call, so `init_db()` and core are untouched and a backup restored from an older version still works). A reminder for a plant follows the plant's home; one for no plant keeps `loc_id`, the home it was written at (`remind_here()`). Routes: `GET/POST /api/reminders` (`?plant=`, `?done=0`), `PUT/DELETE /api/reminders/<id>` (DELETE only sets `removed_at`), `POST/DELETE /api/reminders/<id>/done` (done today; a repeating one inserts its next row `repeat_days` after today and points `done_next` at it; "Not done yet" deletes that row while it is untouched). `remind_get()` refuses an editor limited to other homes (the path carries no plant, so `home_refusal()` cannot see it). Audit action `care`, fields `reminder` / `reminder_done`. Front end `js/reminders.js` (one `addFeature()`: page `#/reminders` in the Today row, Today block `today-remind` at order 69, plant-page add `rm-plant` with `care: true`; acts `rmnew`, `rmedit`, `rmdone`, `rmlater`, `rmundo`, all in the viewer rule in `css/reminders.css`). Checks: `dev/test/unit/test_reminders.py`, `dev/test/reminders_check.py`.
