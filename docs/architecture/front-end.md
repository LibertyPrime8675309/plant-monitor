# The scripts one by one, units, the Plants page, layout

Part of the notes on how Plant record is built. The short map is `docs/ARCHITECTURE.md`; this file holds the detail for one area, moved here word for word on November 15, 2026.

## Notes
- **Units (1.47.0, PLAN.md step 4a).** Everything is stored and sent in °F and inches; only what a person sees changes. `core.js`: `UNIT_REGIONS` (us, ca, metric), `unitsGet()` / `unitsSet()` on localStorage `plantdb.units` (`{region, temp, len, rain}`, only the parts that differ from the region), which `prefs.js` KEYS sync to the server as the `units` setting; `tF(f, unit)` (a °F value in the person's unit, whole degrees for whole input), `tD(df)` (a difference, no offset), `tNum`, `tIn` (typed value back to °F), `tU()`, `lenF/lenIn/lenU`, `rainF/rainU`, `areaF` (sq ft or m²), and `tText()` which converts "N°F" and "N to M°F" inside free text (applied by `linkify`, so notes and server sentences read right). `weather.js` `tempChart()` converts a chart's values, reference lines and bands once when its unit is °F. The edit form (`TEMP_FIELDS`), the group bulk-set, the manual conditions, the light-spot distance and pot sizes show and take the person's unit and store °F and inches. The Display window's Units part (`ui.js`; act `unitset` in `events.js`) saves, pushes the setting to the server at once and redraws from fresh answers. Server (`core.py`): `units_for(c, login)`, `units()` (per request, cached on `g`), `temp_text`, `temp_diff_text`, `rain_text`, `len_text`, `temps_in_text`; `push_send()` takes a callable `(units) -> (title, body)` so each person's push message is in their units; the calendar feed uses the owner's. Checks: `dev/test/unit/test_units.py`, `dev/test/units_check.py`.
- `js/*.js` (1.32.0; `app.js` until then): classic scripts loaded in the order `js/manifest.json` gives (1.46.0: the server writes the `<script>` tags into `index.html` at the `<!--scripts-->` marker and the list into `sw.js` at `__SHELL_JS__`; a new module is one new file plus its name in the manifest, and the unit test `test_registry.py` checks the two agree). Anything that extends `acts` must come after `events.js`. Every route must be listed in `SECTIONS` (core.js) or linked from a listed page; `dev/test/unit` checks it (1.36.0). `?sec=ID` opens a page at a section. Routes (1.34.0): `#/` is Today (`#/today` still works) and the Plants page is `#/plants`; `#/plants?area=ID` or `?spot=ID` (from a room or shelf label) sets the `area`/`spot` filter and rewrites the address to `#/plants`. No name may clash with a `window` property (none does; `dev/test/unit` does not check this, the smoke test would show it as a script error). 1.57.0: `test_js_names.py` checks no top-level name is declared in two files. **1.57.0, one bundle:** `index()` loads `/app.js?v=VERSION`, the manifest's files joined in order by `script_bundle()` (offline.py; built once per process and again when a file changes, ETag, a `/* ==== js/x.js ==== */` line before each part), and `sw.js` saves it in the shell. The bundle is one strict-mode script from core.js's `'use strict'` on, so every file declares `'use strict'` (`test_registry.py`). `PLANTDB_JS=split` in the environment loads the separate files again, for finding a line from a browser error.

## Colours and reading (1.58.0)
- `prefs.js` sets, before the page paints: `data-theme` (light or dark; absent for Match my device), `data-tone` (`cream` for Cream paper, `soft` for Soft dark: the theme is light or dark underneath, so rules for either still apply), `data-mode` (light or dark after Match my device is worked out, updated when the device changes), `data-contrast` (Match my device follows `prefers-contrast: more`), `data-cvd` (`rg`, `by`; absent for usual), `data-font` (`atkinson`, `lexend`, `dyslexic`), `data-plain` (`1`: one plain font, no italics or capitals) and `data-space` (`normal`, `roomy`, `widest`).
- `static/css/01-reading.css` holds the tokens for the new tones and colour-vision settings, the two fonts (`static/fonts/`, OFL), the health-tag symbols, one plain font and Widest spacing. It sorts right after `00-core.css`.
- Display (`ui.js` `displayDialog()`): a Reading part (Easier reading, letter shapes, headings and plant names, spacing, line length). `easyReading()` / `easyUndo()` keep what was there before in localStorage `plantdb.easyprev`. `PlantSync` PARTS: `text` (size, contrast, theme, cvd) and `reading` (font, plain, space, lines); a device that shared `text` before shares `reading` too.
- Checks: `dev/test/unit/test_colours.py` works out the colour tokens for every theme, contrast and colour-vision setting from the stylesheets and measures them (7 to 1; good, fair and poor kept apart under simulated colour blindness), and keeps justified text, capitals and italics out of the stylesheets. `dev/test/reading_check.py` measures every page in Cream paper, Soft dark and red-green colours, looks for sideways scrolling with the strongest reading settings on a phone, and tries Easier reading and a device asking for more contrast. `contrast_js.py` is the measure it shares with `names_check.py`.
